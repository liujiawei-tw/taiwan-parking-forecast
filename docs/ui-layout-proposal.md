# 地圖與結果清單同頁布局提案

更新日期：2026-09-24。狀態：Sponsor 已決定地圖與結果清單同頁、搜尋候選體驗類似 Google Maps；以下布局細節為設計提案，未實作。

## 畫面主次

地圖回答「停車選項在哪裡」；結果清單回答「抵達時有位的可能性、目前觀測、距離、資料何時取得」。路邊 300 公尺區域的有位機率是一張區域摘要，不是每一格位都有個別抵達時機率。路邊當前有空位的格位位置只作次要明細。路外停車場按單場顯示。

## 電腦版（建議寬螢幕）

1. 頂部：目的地搜尋框；次列為起點（目前位置或手動選取）、出發日期時間（預填當下）、Google 估算的目的地 ETA。選好目的地後保持可修改，但不佔用大量地圖面積。
2. 主區：左側固定寬度約 360–420 px 的結果清單，右側地圖使用剩餘寬度。這些像素是原型起點，不是已定的驗收數值。
3. 清單頂部：目的地與「方圓 300 公尺」範圍說明、目前資料取得時間／更新狀態。下方先放路邊區域摘要，再列範圍內的路外停車場；只有實際收錄的類型才顯示。路邊明細展開後列目前有位且已確認適用汽車的格位。
4. 每張結果卡分開標明「抵達時預測」與「目前車位／格位觀測」，附來源時間與品質狀態。資料不足時保留地點資訊與明確說明，不留空白機率。

## 手機版（建議窄螢幕）

1. 頂部保留精簡目的地欄與可展開的起點／出發時間；ETA 和目的地範圍在其下，避免搜尋欄佔滿首屏。
2. 地圖在上、清單在下，兩者為同一頁的自然捲動內容；地圖高度先以約三分之一至二分之一畫面作原型測試，讓第一張結果至少有部分可見。不要先加入複雜的拖曳式底部抽屜。
3. 使用者點選地圖標記時，對應清單卡片被醒目標示並帶到可見位置；點選清單卡片時，地圖定位並醒目標示對應地點。手機上不讓標記資訊視窗遮住整張地圖或取代完整清單。
4. 地圖互動可能與頁面捲動競爭，原型須用真機測試。清單本身應可完成選擇與讀取資訊，不依賴拖曳地圖。

## 2026-09-24 電腦版地圖優先方向（Sponsor 已接受方向，細節未定）

Sponsor 提議電腦版不固定顯示左側完整清單，而以地圖為主：在目的地 300 公尺圓形範圍內顯示簡要標記，點選後才開詳細結果。Sponsor 已同意保留固定區域摘要與「查看全部結果」入口作為地圖優先方向；具體互動仍要與常駐清單草圖比較，詳見 `ui-wireframe-comparison.md`。此方案適合先看相對位置；風險是選項多時難以比較，路邊「區域至少一格」的抵達時機率也沒有單一格位標記可代表。因此建議採折衷的地圖優先方案：

- 地圖維持主要畫面；上方／側邊固定一張精簡區域摘要，至少顯示目的地 ETA、路邊區域抵達時機率、資料時效與結果數。若附近沒有路邊類型，則不顯示該機率。
- 路外停車場在地圖上各有標記；路邊格位標記只表示「目前來源回報有位且已確認適用汽車」，不得標成該格抵達時的預測。格位密集時分群或縮放後才顯示。
- 點標記先開精簡資訊（名稱／類型、目前狀態與時間、抵達時預測若有），再點「查看詳細」開側邊清單／詳情面板；保留明顯的「查看全部結果」入口供比較、鍵盤操作或標記重疊時使用。
- 手機仍維持已討論的上地圖／下清單方向；不強迫把電腦版的隱藏清單操作照搬到手機。
- 地圖平移、標記點選、開關詳情不觸發新的政府、Places 或 Routes 請求；只有使用者明確重整或改變目的地／出發設定才走對應受控流程。

電腦版地圖優先方向已獲同意，但常駐左清單仍保留為比較基準；用草圖測試能否在未點標記時回答核心問題、能否快速比較兩座停車場，以及多格位重疊時是否仍找得到結果，再定具體布局與互動。

## 2026-09-24 導航到目前回報有位的汽車格位（提案，未定案）

使用者點選已核實為一般汽車可停、位置有效且目前觀測仍在可接受時效內的格位，可在詳情提供「開啟外部地圖路線」；選 Google Maps 或 Apple Maps，目的地為該格位座標，駕車模式。這是開啟外部路線頁，使用者仍需確認並開始導航，不保證外部地圖能精準停在該車格側，也不代表車位被保留。Google Maps URLs 可帶目的地座標與 driving；Apple Map Links 可用 daddr 及駕車參數，詳細連結形式待實作時按官方文件核對。

導航按鈕旁需顯示「目前回報有位」及系統取得時間，並提醒「抵達時可能已被使用」。若車位狀態過期、未知、位置不可信或汽車適用性未確認，不能沿用「有位」文案；可僅提供中性的「查看位置／路線」並標示狀態未確認，或暫不提供該格位導航。出發時間設為未來時，按鈕文案宜為「查看路線」；只有使用者明確選擇立即出發時才稱為「開始導航」。外部地圖重新計算的 ETA 可與本產品的目的地 ETA 不同。

待確認：格位座標精度、是否能安全定位到道路可進入側、路邊特殊格位排除條件、過期時是否保留中性路線入口，以及 Google／Apple 的選擇方式。

## 地圖與清單同步規則

- 地圖保留目的地標記與 300 公尺圓形範圍；路外以停車場標記表示，路邊主預測以範圍摘要呈現，不假裝每格都有個別預測。
- 路邊目前有位的格位點，先在使用者展開「查看目前空位位置」後顯示；標記多時分群或隨縮放逐步揭露，避免遮住停車場。來源狀態碼／車種資格未核對前，不顯示為確定可停標記。
- 地圖與清單以同一筆系統內 ID 選取，不因選取標記或捲動清單而重新呼叫 Google 搜尋、Routes 或政府即時資料。只有明確重新整理或修改搜尋條件才重新走受控資料流程。
- 使用者平移地圖不改變已選目的地的 300 公尺查詢範圍；顯示「回到目的地」以避免地圖位置與結果範圍不一致。是否另加「搜尋這個區域」屬後續功能。
- 路邊／路外視覺符號除了顏色也用文字或形狀區分；標記應有可辨識名稱及鍵盤操作，清單保留完整等價資訊。

## 第一版標記點選流程（下一輪討論提案）

1. 地圖初始保持目的地 300 公尺圓、固定的路邊區域預測摘要與「查看全部結果」。停車場標記代表單場；路邊格位標記只代表目前觀測且核實適用汽車的個別格位。
2. 點停車場標記：先開小型資訊卡，顯示名稱、距離、目前剩餘位及取得時間、抵達目的地 ETA 對應的該場有位機率或「預測資料不足」。按「詳細資訊」開側邊面板；按路線按鈕交給外部地圖。
3. 點路邊格位標記：小型資訊卡顯示位置、目前回報有位、資料取得時間與時效，並直接提供「查看路線」入口；Sponsor 已選定入口放在小卡。不可把 300 公尺區域機率寫成該格位的抵達時機率。若格位狀態或汽車適用性未確認，不提供「目前有位」稱呼。
4. 點固定摘要或「查看全部結果」：開完整清單面板，提供路邊區域摘要、目前有位格位明細與各停車場，可在不逐點標記的情況下比較。選擇項目與地圖標記互相定位。
5. 點選標記、開面板或地圖平移不重新呼叫來源；顯示的車位與預測時間、品質沿用已取得結果。使用者明確重新整理時才走主系統的受控刷新。

小卡直接提供格位外部路線入口已決定；其餘資訊層級仍需用草圖測試小卡是否太擠、路線入口是否易辨識與誤觸風險。
