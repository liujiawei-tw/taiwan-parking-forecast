# Sprint 3 預測進入條件

更新日期：2026-09-29。狀態：S2-025 文件基線；這是進入 Sprint 3 預測工作的工程門檻，不是模型已完成或準確率承諾。

## 目的

Sprint 3 可以開始處理抵達時預測，但只能在資料、標籤、基準與推論契約可被驗證時，才把結果呈現為機率。若任一條件不足，主系統必須維持 `INSUFFICIENT_DATA` 或對應失敗狀態，不以目前車位、隨機值或人工估計冒充模型輸出。

本文件只規範主系統和未來離線訓練／回測的進入條件。獨立 `parking-data-collector` 仍不服務使用者查詢，也不能取代主系統的官方即時快照與發布紀錄。

## 目前基線

已完成：

- 後端已有停車目錄、來源 mapping、候選／已發布快照、觀測歷史、來源狀態與 ingestion run 量測摘要。
- 使用者查詢已透過 Redis 保存短期 query state，`GET` 只讀既有狀態，車位刷新不重算 Google ETA。
- 前端已有 Google Maps／Places 載入路徑、手動座標 fallback、地圖優先結果頁與可見頁受控刷新接線。
- 新北市官方 Open Data 已有低頻單輪量測：路邊 30,941 rows／11,270,904 bytes／4,600 ms；路外 1,407 rows／50,642 bytes／1,011 ms。
- S2-020 小樣本 mapping 在該單輪量測中可被找到：路邊 7/7、路外 3/3。

尚未完成：

- 多輪官方來源量測，因此沒有 p50／p95、失敗率、長期 cooldown 或正式服務門檻。
- 真實 browser key 的 Places 人工驗收，以及 S2-024 端到端官方刷新人工驗收。
- 路邊 300 公尺區域與路外單場的訓練標籤匯出、時間切分回測、基準模型比較與模型產物版本化。

## 硬性進入門檻

Sprint 3 開始輸出任何預測機率前，至少要滿足下列條件。

1. **來源量測可重現**：路邊與路外各有多輪量測紀錄，包含 HTTP 次數、頁數、回應 bytes、延遲、row 數、缺 source ID、重複 source ID、來源欄位異常、mapping 覆蓋、發布建議與失敗原因。單輪量測只可作設定初值，不可作穩定性承諾。
2. **完整性與覆蓋界線清楚**：目錄、mapping 與 300 公尺查詢範圍必須知道是完整、部分或未知。路邊若只能覆蓋部分格位，不得輸出「整個 300 公尺圓內至少一格可停」的完整區域機率。
3. **標籤規則與線上定義一致**：路邊訓練標籤須用線上同一套目的地圓心、直線 300 公尺、一般汽車資格、有效觀測比例與時間對齊規則建立；路外訓練標籤須以單一 verified lot mapping 建立。未知、過期、負值特殊碼、候選／拒絕快照不可當成 0 或真實標籤。
4. **時間切分無洩漏**：模型訓練只能使用 `asOf` 當時已取得的資料，不能使用抵達後才知道的觀測。回測須採時間順序切分；路邊任意圓形樣本還需檢查不同圓心或區域的泛化風險。
5. **基準模型先行**：至少先建立可解釋基準，例如維持目前狀態、同時段歷史平均或簡單邏輯模型，再和候選 ML 模型比較。評估指標、接受門檻與失敗時的顯示狀態須在模型結果出來前定義。
6. **推論契約完整**：可輸出機率時必須同時回 `modelVersion`、`generatedAt`、`targetArrivalAt`、輸入快照版本、資料年齡、適用時距與主要拒絕原因。模型版本未載入、ETA 失敗、資料過期且刷新失敗、覆蓋不足或超出驗證時距時，只能回資料不足或失敗。
7. **營運邊界可回滾**：模型產物須可版本化與回滾；線上查詢不得即時計算訓練或依賴 collector。主系統查詢要能在模型不可用時保留目前車位與 ETA 顯示，並把預測區塊獨立降級。

## 可先做的 Sprint 3 工作

即使硬性門檻尚未全部滿足，也可以先做下列低風險工作：

- 匯出主系統已發布觀測歷史的離線資料集，並排除 `CANDIDATE`、`REJECTED`、過期與品質不足資料。
- 建立路邊／路外標籤產生器的 dry run 報告，只輸出 row 數、可用比例、缺口與拒絕原因，不訓練正式模型。
- 製作基準模型回測 notebook 或批次報告，先以小樣本驗證時間切分、資料年齡與評估指標。
- 將 API 的 `predictions` 區塊維持為資料不足，但補齊模型版本未載入、覆蓋不足、ETA 缺失等可解釋原因。

## 目前不可做的事

- 不用目前有位數直接推抵達時機率。
- 不把單輪官方 API 成功當成長期穩定性。
- 不把部分 mapping 的結果包裝成完整新莊覆蓋。
- 不把 collector 的 CSV、排程或時間戳當成主系統使用者查詢契約。
- 不提交原始 API 回應、用量細節中的敏感設定、Google 或 TDX 金鑰。
