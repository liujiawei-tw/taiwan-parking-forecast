# 路線圖與一人 Scrum

更新日期：2026-09-23。以下是順序，非已承諾的日期。20 天是否足夠，取決於每日可投入時間與 API 資料品質。

## Product Goal

展示一個可查詢 TDX 停車場、說明資料品質，並對有足夠歷史的停車場提供抵達時有位風險評估的原型。

## Sprint 0：需求與資料可行性（目前）

交付：文件、TDX 端點／點數盤點、統一資料契約草案、MVP 驗收條件。退出條件：知道第一個端點、擷取預算及第一版展示範圍。

## Sprint 1：資料進入系統

交付：TDX 認證與擷取、原始／標準化資料、MySQL 保存、資料時間與錯誤記錄。範例程式以 TDX 官方 Java SampleCode 為依據。

## Sprint 2：查詢與額度保護

交付：使用者查詢本地資料、簡單網頁、Redis 快取、配額保護與過期顯示。Redis 的節省效果由實際呼叫數與查詢負載衡量。

## Sprint 3：預測與展示

交付：歷史資料分析、簡單基準、時間切分回測、可解釋結果與面試展示文檔。若歷史資料不足，展示可量化的資料可行性與明確的預測限制，不編造準確率。

## 後續

接地方政府 API、合併重複停車場、增加路線時間來源、改良模型與維運監測。

## 工作節奏

- GitHub Issue：一件可完成的工作，包含驗收條件。
- GitHub Projects：Backlog／Ready／In Progress／Review／Done，配 Iteration。
- 每個 Sprint 先定目標，結束時展示增量、檢視指標、記錄下一步。
- 小且有意義的 Git commit 應在工作進行時持續建立；完成可運作的小段落就推送到私人或適當權限的遠端，不必等全部做完，也不必每按一次儲存就推送。
- 一人 PR 可作自我審查與面試展示；重大變更先記設計理由。

## Definition of Done 草案

功能符合該 Issue 的驗收條件，資料異常有處理方式，必要測試通過，文件與 `current-state.md` 已更新，金鑰未進 Git，且可從乾淨環境重現。
