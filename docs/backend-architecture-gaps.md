## 建議討論順序

1. 先鎖定**主系統即時來源擷取與刷新控制**：它同時影響資料新鮮度、多人查詢、上游用量與首次等待。
2. 再定**API 回應契約**，使 Vue 可獨立處理 ETA、路邊、路外、預測的完成和失敗。
3. 接著定**模型推論契約**，避免先有畫面卻無法解釋機率來自哪些樣本與資料品質。
4. 最後收斂**Google 服務預算與部署拓樸**；具體效能優化於實測後決定。

每項需有一個可展示的異常案例，例如官方來源失敗、明確 0 位、未收錄、資料過期、ETA 失敗或容器重啟。討論完成不等於實作完成；Sprint 1 的退出條件是主要輸入／輸出、來源預算與失敗行為可供開發與驗收。
