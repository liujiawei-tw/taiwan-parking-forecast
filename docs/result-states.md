# 查詢結果與資料不足時的顯示規則（Sprint 1 草案）

更新日期：2026-09-24。狀態：需求草案；尚未實作。範圍為搜尋目的地周圍 300 公尺內、目前收錄且適用汽車的路邊與路外資料。路邊與路外同頁依實際資料顯示，不要求兩種都存在。

## 已確認的分階段結果頁狀態方向

Sponsor 已同意建立查詢後，目的地與可信位置先顯示，ETA、路邊、路外及抵達時預測各自完成後補上；並同意**各區塊有自己的狀態**，不讓整頁一直轉圈，也不強迫它們按固定順序完成。地圖維持目的地與 300 公尺範圍；只有 MySQL 停車目錄可信時才畫已收錄停車位置。下表是已同意的語意，具體文案待原型驗證。

| 區塊狀態 | ETA 區塊 | 路邊區域／路外場站的目前車位 | 抵達時預測 |
| --- | --- | --- | --- |
| 載入中 | 「正在計算預計抵達時間」 | 「正在取得車位資訊」；若已收錄位置可信，可先顯示中性位置標記 | 「等待抵達時間與可用資料」；不顯示暫定百分比 |
| 完成 | 顯示 Google ETA、路線計算時間與使用者選定的出發時間 | 顯示有效目前數值（包含有效 `0`）、資料來源與時間；路邊個別有位標記只限已確認適用汽車且觀測新鮮 | 路邊顯示 300 公尺內至少一格可停機率；路外逐場顯示有位機率，附目標 ETA 與模型依據 |
| 失敗／工作到期 | 「暫時無法估算抵達時間」；其他車位區塊仍可用 | 保留可信位置，顯示「目前車位無法確認」及可用的上次取得時間；另一來源不受影響 | 若缺 ETA 或可信觀測則不產生機率，說明缺哪個條件；不可沿用上一次查詢的 ETA |
| 資料已過期 | ETA 不套用車位 5 分鐘門檻；原抵達時刻已過則提示明確重新規劃 | 可見頁面先受控嘗試刷新；主要目前可用數留空，舊數值只在附時間的次要資訊顯示，不標「目前有位」 | 若模型要求近期觀測而無新資料，顯示「預測資料不足」；不以過期資料輸出看似精確的機率 |
| 真正沒有收錄／來源未知 | 不適用 | 已核實收錄範圍且符合條件的項目為 `0`，才顯示「目前收錄資料中沒有選項」；目錄未知時顯示「位置資料無法確認」 | 路邊圓形範圍覆蓋不完整或未知時，不宣稱完整 300 公尺的機率 |

**互動方向**：每張卡顯示最近資料時間；「更新車位」只對路邊與路外做受控刷新，不重算 Google ETA。失敗、過期、有效 `0`、沒有收錄、預測資料不足都用不同文案與狀態；地圖標記不可用單靠顏色區分。若某區塊工作已到期限，停止載入動畫，提供可理解的狀態或下一步。具體文案、版面與 API 狀態值尚待 Sponsor／原型確認；這段不是已完成的前端。

## 已確認的「更新車位」按鈕反應

建議結果頁維持**一個「更新車位」入口**；按下後，後端分別檢查路邊與路外來源。這是對目前觀測的更新，不改起訖點、出發時間或 Google ETA，也不保證每按一次就呼叫官方 API。若同時已有自動或其他使用者啟動的刷新，加入同一輪，按鈕避免重複啟動。

| 該來源目前狀態 | 使用者按下後看到 | 系統對該來源的行為 |
| --- | --- | --- |
| 已有有效且未過期快照 | 「目前顯示系統於 HH:mm 取得的資料」；數值和時間維持 | 直接回共用快照，不因按鈕再抓一次 |
| 無快照或資料過期，且允許刷新 | 該來源顯示「正在更新車位資訊」，另一來源仍可用 | 啟動每來源一輪共用擷取；同時其他查詢加入，不另開一輪 |
| 已有刷新在進行 | 維持「正在更新」，按鈕暫不再送出；其他結果照常顯示 | 加入既有工作，只等完成訊號或讀進度 |
| 來源冷卻、用量限制或尚未允許再抓 | 「目前暫時無法更新」，如有可再試時間則顯示；保留位置及上次取得時間 | 不繞過限制、不緊密重試；過期的主要可用數仍為空 |
| 刷新完成，但來源觀測與上次相同 | 顯示本次系統取得時間；若有可信來源觀測時間，保留並顯示它 | 不把同一份來源觀測冒充剛產生的新空位 |
| 擷取失敗或工作到期 | 結束載入，顯示「更新失敗，目前車位無法確認」及上次成功時間 | 不發布不完整快照；另一來源的有效結果不受影響 |

新完整快照若成功發布，而原 Google ETA 仍在未來，可在模型條件合格時重新推論**同一 ETA 目標時刻**；若原 ETA 已過，提示明確重新規劃，不能默默重算 Google 路線。進度等待須有上限，具體秒數由正式來源完整擷取耗時決定。互動語意已由 Sponsor 同意；文案、進度欄位、等待秒數仍待原型與實測，尚未實作。

## 已確認：自動刷新與手動更新同時發生

頁面可見且資料過期時的自動嘗試，以及使用者按「更新車位」，都走同一後端來源級刷新操作。前端同一頁面發現來源已有待處理請求時，不重複送出；即使其他分頁或使用者同時請求，後端仍以來源級單輪工作作最後防線。手動按鈕可查詢／加入既有工作的進度，不額外開一輪官方擷取。

頁面隱藏時暫停自動觸發及輪詢。重新可見時，先讀一次目前狀態，再按各來源資料時間、執行中狀態及可再試時間判斷。已新鮮的來源直接顯示；冷卻或失敗後不可用定時器反覆觸發。具體自動重試次數／間隔待來源量測。

畫面維持一個按鈕，路邊與路外各有「已是最新取得資料」、「正在更新」、「暫時無法更新」等獨立回饋及時間。系統取得時間與來源實際觀測時間要分開；取得到相同來源觀測時不得宣稱空位狀態剛更新。所有車位更新均不重算 Google ETA。

## 已確認：來源擷取失敗後的重試

官方車位來源擷取失敗時，該來源立即停止載入並顯示「目前車位無法確認」及最後成功取得時間；路邊與路外分開處理，某一來源失敗不影響另一來源的有效結果。後端以來源級冷卻保護官方 API，跨使用者、分頁、自動刷新、手動更新及背景取樣共用同一個 `nextAllowedAt`；冷卻或用量限制內不得再次呼叫官方來源。

頁面仍可見且資料過期時，冷卻後最多共用地自動重試一輪。若仍失敗，停止自動重試，之後只接受使用者手動按「更新車位」觸發檢查；手動更新也只能在來源允許、預算允許且沒有同來源工作進行中時啟動。所有重試都不重算 Google ETA。

過期舊數值只可作附原資料時間的次要參考；主要目前可用數仍為空，舊「有位」格位不可作目前推薦或導航依據。具體冷卻時間、錯誤分類、等待上限與 API 欄位待來源量測；5 分鐘是資料新鮮度試驗門檻，不是重試冷卻時間。

| 情況 | 建議顯示 | 不可暗示 |
| --- | --- | --- |
| 300 公尺內兩類都有 | 同頁分別標示路邊及停車場，保留各自數量、時間與品質 | 兩類數字可直接相加成同一預測 |
| 只有其中一類 | 顯示有資料的類型 | 另一類已滿 |
| 沒有收錄任何適用選項 | 「目前沒有收錄這個範圍內的汽車停車選項」並標示資料覆蓋範圍 | 現場一定沒有停車位 |
| 目錄已核對且 300 公尺範圍完整涵蓋，但已收錄汽車選項為 0 | 「目前收錄的資料中，這個範圍沒有符合條件的停車選項」；可提示改搜附近地點 | 現場所有公私有或未收錄車位都不存在 |
| 目的地超出新莊試點 | 保留已選地點，明示「目前尚未支援此地區」及改搜入口；不呼叫 ETA 或官方車位來源 | 空清單等於附近沒有車位 |
| 目的地在新莊內，但 300 公尺圓部分未收錄 | 保留 ETA 與已收錄選項；路邊完整範圍的抵達時機率寫「部分區域未收錄，暫無法預測完整範圍」。合格路外場站仍可各自顯示單場預測，註明附近清單可能不完整 | 已收錄部分的路邊機率等於完整圓形機率、未收錄部分等於 0 |
| 無法確認路邊資料是否完整覆蓋 300 公尺圓 | 顯示已核實位置；路邊完整範圍機率寫「覆蓋範圍未確認，暫無法預測完整範圍」。合格路外場站可各自顯示單場預測，另標示清單覆蓋情況 | 目的地在新莊就必然完整涵蓋 |
| 停車目錄尚未取得或查詢失敗 | 標示位置資料暫時無法確認，提供重試或改搜；不宣稱搜尋完成後沒有選項 | 來源失敗等於 0 筆停車選項 |
| 有場站／格位，但沒有有效即時觀測 | 保留名稱和位置，車位寫「目前無即時車位資料」 | 剩餘 0 位 |
| 即時觀測為有效 0 | 寫「目前 0 位」、來源與取得時間 | 未知或資料壞掉 |
| 最新成功取得超過 5 分鐘 | 結果頁可見時自動嘗試一次受控共用刷新，等待上限內顯示「正在更新車位資訊」；頁面隱藏時暫停。成功後呈現新快照；失敗或暫不能呼叫時保留地點，寫「目前車位無法確認；上次取得於 HH:mm」，不自動密集重試。主要目前可用數留空，舊數值如需展示只放附原時間的次要詳情 | 舊「有位」格位仍可當目前空位推薦、剛抓到就等於來源剛更新 |
| 路線 ETA 無法取得 | 保留可用的目前停車資訊；抵達時間寫「暫時無法估算」 | 用固定分鐘數或舊 ETA 假裝新的估算 |
| ETA 有效，但模型／訓練資料不足 | 顯示目前觀測；抵達時欄位寫「預測資料不足」並簡述原因 | 虛構機率或用目前車位冒充抵達時車位 |
| 來源回傳部分格位 | 顯示已觀測筆數／預期筆數；低於最低覆蓋率時不輸出「至少一格」預測 | 未回報的格位都是已滿 |
| 完全沒有可用資料 | 說明是哪個服務或範圍無資料，提供重試或改搜其他地點 | 空白畫面或通用「發生錯誤」 |

產品設計提案：將「搜尋沒有結果」（empty state）、「上游服務失敗」（error）、「資料過期」（warning）和「模型無法預測」（insufficient data）分開。訊息要說明使用者下一步能做什麼，例如改搜地點、稍後重試、查看最後取得時間。這與 Atlassian 的空狀態／錯誤訊息指引及 GOV.UK 明確錯誤訊息指引的原則相符；具體文案仍需用原型驗證。

Sponsor 已確認「無即時資料」、「預測資料不足」、「ETA 暫時無法估算」、「有效 0 位」及「範圍內未收錄」五種情境的分別呈現。超過 5 分鐘的判斷門檻已選為第一版測試值，但警示文案及使用者接受度未定案；不能宣稱一般使用者必然接受。以最後成功取得時間判斷時，必須標清這是系統取得時間，不能冒充來源實際觀測時間。若來源提供可靠觀測時間，另顯示或優先檢查該時間。超過門檻時應優先在受控刷新與呼叫預算內取新資料，更新期間與更新失敗分開顯示；舊「有位」格位不可留在目前可停標記或導航推薦。抵達時預測若仍可產出，須與目前觀測的時效分開標示；若無可靠依據，顯示預測資料不足。

待原型驗證：讓至少幾位試用者查看 4～5 分鐘、6～10 分鐘及更新失敗的畫面，確認能否分辨「目前 0 位」、「沒有資料」與「資料較舊」，能否找出最後取得時間，以及是否知道可等待更新或改看其他選項。再依實測調整門檻與文案。

「300 公尺」已由 Sponsor 選定為目的地座標的地圖直線距離；本期不以步行可達距離取代。靠近新莊行政區邊界時，如果來源只收新莊，必須標示範圍覆蓋不完整，避免把鄰區未收錄誤認為沒有車位。路邊個別格位的汽車適用性及狀態碼未核實前，不顯示確定可合法停放的數量或機率。
