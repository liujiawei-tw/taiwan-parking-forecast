# 停車歷史資料取得與 ML 試驗計畫

查核日期：2026-09-23。來源：[TDX 歷史服務清單](https://tdx.transportdata.tw/data-service/historical)、[停車歷史 API 說明](https://tdx.transportdata.tw/api-service/swagger/historical/bfc9dd07-b597-4851-b20f-82f2c53a0fe1#/OffStreetParkingCityAPI/Historical_ParkingCityAvailability)、[TDX 訂閱收費](https://tdx.transportdata.tw/pricing)。以下是資料取得計畫，尚未用會員帳戶申請或下載檔案。

## 清單與候選資料

TDX 歷史服務的「停車資訊 18」表示 18 種資料集，並非一定要下載 18 份。頁面列出縣市路外停車場剩餘位資料：基隆、宜蘭、桃園、臺南、花蓮、高雄；另有路邊停車及機場、高鐵、高速公路等資料。MVP 的汽車路外預測先選**桃園市停車場剩餘位歷史資料 v1**作為一個候選資料集。這是規劃上的選擇，仍要用小樣本檢查有效停車場數、汽車車位含義、缺值率與時間密度。

桃園資料頁列出的供應區間是 2024-03-10 至 2026-09-22，提供 CSV／JSONL，頁面標示每日更新。資料列範例含 `CarParkID`、`TotalSpaces`、`AvailableSpaces`、`ServiceStatus`、`FullStatus`、`DataCollectTime` 等欄位；「每日更新」是資料供應頻率，不能據此推定每座停車場的觀測粒度。

## 日期與資料切分

2024–2025 年位於供應區間內，可以作為較長期的季節性研究，但不建議第一步直接取得完整兩年。先取**一個最近的完整 7 天區間**驗證檔案格式、觀測密度、車位語意、缺值與檔案大小；如果合格，再擴成數週或數月。之後按時間先後切分訓練與測試，不隨機打散時間序列；另取 2026 年較新的一段做樣本外驗證，避免只用 2024–2025 年資料評估現況。

一週小樣本只能證明資料管線可行，通常不足以證明模型在不同節日、季節或異常事件下可靠。是否需要兩年資料，應在基準模型與資料漂移檢查後再決定。

## CSV 或 API

- **第一次探索：優先用 TDX 網站申請 CSV 小範圍檔案。** Jupyter 可直接讀取；便於檢查欄位、時間順序、缺值與體積，且不必先寫下載程式。申請前查看頁面是否顯示預估檔案大小或耗點，避免超出 3 點預算。
- **後續可重現擷取：再使用官方歷史 API。** API 要依 TDX 官方 Java 範例實作認證；用固定日期區間、記錄請求與回應，適合排程與資料治理。
- API 說明顯示 `Dates` 單次最多 7 日，`$top` 預設 30，格式有 CSV／JSONL，`Meta=true` 可查 Count 和 SizeBytes。若未確認完整筆數與分頁方式，不能假設一次 API 回應就是整週所有資料。Meta 查詢是否耗點、網站檔案申請的日期上限與點數計法，尚待帳戶頁或官方說明確認。

## 點數風險

歷史服務頁面定價為每 10 次／點加上每 20 MB／點，兩項併計。若透過 API 每次最多 7 天，2024–2025 約 731 天，至少要約 105 個日期區間；即使每區間只需一次請求，僅計次已約 10.5 點，超過每月 3 點，且未算分頁與資料量。因此不以「一次抓完 2024–2025」作為本月計畫。

## 第一份檔案的驗收

取得一個小區間後，先記錄檔名、來源、日期、大小、申請前後點數，再檢查：停車場 ID 數量、每場每天觀測數、`DataCollectTime` 是否連續、車位數是否出現負值或異常跳動，以及能否對應目前 TDX 停車場基本資料。原始檔不要直接提交 Git；只提交不含金鑰或敏感資訊的資料字典、統計摘要與可重現的分析步驟。
