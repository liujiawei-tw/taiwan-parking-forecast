# 停車歷史資料取得與 ML 試驗計畫

查核日期：2026-09-23。來源：[TDX 歷史服務清單](https://tdx.transportdata.tw/data-service/historical)、[停車歷史 API 說明](https://tdx.transportdata.tw/api-service/swagger/historical/bfc9dd07-b597-4851-b20f-82f2c53a0fe1#/OffStreetParkingCityAPI/Historical_ParkingCityAvailability)、[TDX 訂閱收費](https://tdx.transportdata.tw/pricing)。Sponsor 已下載新北市路邊格位與桃園機場路外停車 ZIP；最初兩筆實扣合計 0.68 點。其後新增新北市路邊格位 2026-08-27 與路邊路段 2026-08-25～31，均已購買；申請頁預估分別為 0.97、1.02 點，實扣待核對。完整清單見 `new-taipei-historical-inventory.md`。新北市 2024-04-01 至 2026-07-31 另案已申請，待 TDX 產製。

## 清單與候選資料

TDX 歷史服務的「停車資訊 18」表示 18 種資料集，並非一定要下載 18 份。Sponsor 已取得**新北市路邊停車格位動態歷史資料 v1**作為第一個路邊資料探索對象，並取得桃園機場路外資料作為路外試點候選。路邊「單一格位狀態」、路邊「路段剩餘位數」與路外「停車場剩餘位數」是不同資料單位。新北市路段剩餘位資料屬路邊，不是新莊路外停車場訓練資料；兩種產品預測目標要分開驗證。

Sponsor 另已下載**桃園國際機場路外停車剩餘位歷史資料**（2026-09-01 至 09-22），作為路外試點候選。檔案盤點見 `airport-data-profile.md`。這份資料屬機場停車場，使用情境可能與一般市區停車場不同，不能直接以此宣稱全臺市區路外停車預測準確。

新北市路邊格位歷史 API 範例欄位包含 `ParkingSpotID`、`ParkingSegmentID`、`ServiceStatus`、`SpotStatus`、`DeviceStatus`、`ChargeStatus`、`DataCollectTime`。API 有 CSV／JSONL 格式，日期查詢最多 7 天，`$top` 預設 30。正式分析前仍須確認格位 ID、狀態碼和車種的實際語意。

## 日期與資料切分

新北市路邊格位單日已有約 300–550 萬筆。Sponsor 已取得 2026-08-09，實際 **2,938,401 列**；ZIP 約 9.68 MB、解壓 CSV 約 145.29 MB，此筆實扣 0.56 點。資料盤點見 `new-taipei-data-profile.md`。單日資料可驗證格式與清理流程，但不足以驗證跨日預測。Sponsor 已另申請 2024-04-01 至 2026-07-31 長區間；待產製完成後先確認點數、完整性與實際日期覆蓋，再決定訓練切分。

一週小樣本只能證明資料管線可行，通常不足以證明模型在不同節日、季節或異常事件下可靠。是否需要兩年資料，應在基準模型與資料漂移檢查後再決定。

## CSV 或 API

- **第一次探索：使用已取得的 CSV。** Jupyter 可直接讀取；便於檢查欄位、時間順序、缺值與體積，且不必先寫下載程式。新北市單日檔已成功取得，新增日期前須查購買頁預估點數及剩餘額度。
- **後續可重現擷取：再使用官方歷史 API。** API 要依 TDX 官方 Java 範例實作認證；用固定日期區間、記錄請求與回應，適合排程與資料治理。
- API 說明顯示 `Dates` 單次最多 7 日，`$top` 預設 30，格式有 CSV／JSONL，`Meta=true` 可查 Count 和 SizeBytes。若未確認完整筆數與分頁方式，不能假設一次 API 回應就是整週所有資料。Meta 查詢是否耗點、網站檔案申請的日期上限與點數計法，尚待帳戶頁或官方說明確認。

## 點數風險

歷史服務頁面定價為每 10 次／點加上每 20 MB／點，兩項併計。Sponsor 帳戶每月 3 點，已確認新北市單日**實扣 0.56 點**、桃園機場 22 日**實扣 0.12 點**，合計 **0.68 點**。其後另有兩筆已購買申請，頁面預估點數合計 1.99 點，實扣尚未核對；因此不再用最初兩筆推算可用餘額，應以會員中心統計為準，並納入待產製的長區間申請。新北市解壓 CSV 約 145.29 MB，購買頁顯示檔案 9.2 MB；因此先前用解壓後每列大小推算扣點的假設不成立。後續預算應依每筆申請的頁面預估與實扣紀錄，而非單靠 CSV 大小或列數。

另若透過 API 每次最多 7 天，2024–2025 約 731 天，至少要約 105 個日期區間；即使每區間只需一次請求，僅計次已約 10.5 點，超過每月 3 點，且未算分頁與資料量。因此不以「一次抓完 2024–2025」作為本月計畫。

## 第一份檔案的驗收

每次取得資料，記錄檔名、來源、日期、壓縮與解壓大小、頁面預估及實扣點數。路邊檢查格位 ID、狀態碼、時間間隔、缺口和重複鍵；路外檢查停車場 ID、車種／分區、車位數與更新間隔，並確認能否對應即時資料。原始檔不要直接提交 Git；只提交不含金鑰或敏感資訊的資料字典、統計摘要與可重現的分析步驟。
