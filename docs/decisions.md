# 決策紀錄

以下只記錄已明確採納的方向。草案與尚待驗證的選項請放到 `open-questions.md`。

## 2026-09-23：以 TDX 作為第一個全臺資料入口

- **原因**：先用統一平台盤點全臺可用資料，再依資料缺口增加地方政府 API。
- **影響**：全臺是查詢範圍；即時資料與可預測覆蓋率需逐縣市實測。
- **狀態**：已決定。

## 2026-09-23：建立可維護的資料統一化層

- **原因**：TDX 與地方政府 API 的格式及停車場識別方式可能不同。
- **影響**：來源資料保留原始識別與時間；轉換後使用共同資料契約；路外與路邊資料保留類型差異；前端可以統一呈現。
- **狀態**：已決定；具體資料表仍是草案。

## 2026-09-23：採用一人 Scrum 與 GitHub 管理工作

- **原因**：專案兼具實作與面試展示目的，需要可見的需求、決策、增量與歷史。
- **影響**：文件記方向與決策，Issue 記可執行任務，Projects 管理 Sprint，Git 記變更。
- **狀態**：已決定；Sprint 長度仍可調整。

## 2026-09-23：TDX 介接以官方文件與 Java SampleCode 為依據

- **原因**：避免用過時或第三方的認證與端點範例。
- **影響**：寫 TDX 程式前核對官方 Swagger、費率及 SampleCode。
- **狀態**：已決定。

## 2026-09-23：按 TDX 真實點數計價規劃擷取

- **原因**：免費基礎會員額度有限，服務還有每分鐘存取頻率限制；進階服務與歷史服務單次耗點較高。
- **影響**：先做端點、回應大小及每月擷取次數預算；使用者查詢本地資料，不直接觸發 TDX 擷取。詳見 `tdx-data-and-cost.md`。
- **狀態**：已決定；實際擷取頻率仍待測量。

## 2026-09-23：AI 補值只作估計，不偽裝成即時觀測

- **原因**：來源缺漏時，模型可能提供參考，但無法把缺失的實際車位數變成確定事實。
- **影響**：觀測、估計、未知有不同狀態；資料缺口過大時不預測。
- **狀態**：已決定。
