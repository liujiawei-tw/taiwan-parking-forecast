兩份新 ZIP 已解壓，並核對 CSV 標題列與檔案大小；以下是初步唯讀盤點，不是完整資料品質驗收。8/27 格位檔有 5,484,110 列、31,329 個格位 ID；以目前新莊即時來源的 2,124 個格位 ID 篩出 359,910 列，2,124 個 ID 均可對上。路段七日檔共 3,907,867 列；以目前新莊的 81 個非空路段 ID 篩出 341,473 列，81 個 ID 都在檔案中。

路段名稱含「新莊」的歷史資料有額外 ID `RA1`，且部分路段 ID 空白；目前 ID 清單只適合做初步子集，不能宣稱涵蓋全部歷史新莊路段。七日已對上路段的 `SpaceTypeAvailableSpaces` 全部為 0，然而 `AvailableSpaces` 多數大於 0；車種剩餘位欄位不可直接當模型標籤，總剩餘位也不能跨 `SpaceType` 列加總。8/27 格位與路段資料日期重疊，可用於核對相同路段、相近時間的觀測，但兩種資料的涵蓋與狀態語意不可預設相同。

TDX [停車資料入門指引](https://motc-ptx.gitbook.io/tdx-zi-liao-shi-yong-kui-hua-bao-dian/ling-yu-zi-liao-ru-men-zhi-yin/ting-ju-zi-liao-ru-men-zhi-yin)將路邊格位、路邊路段與路外停車場分為不同資料類型；動態資料需結合靜態基本資料，才能取得位置、行政區及車位類型。歷史下載頁和對應 Swagger 公開顯示的條件沒有行政區篩選，不能假設先篩新莊會降低購買點數。現有新莊即時格位 ID 與 8/9 TDX 檔的初步交集為 2,124 個 ID、103,748 列；目前 ID 清單可能漏掉已移除的歷史格位，尚不是完整的新莊歷史範圍。

下一步：核對實扣點數、取得路段／格位靜態資料或可靠對照表，釐清路段車種欄位全零原因，檢查 ID、缺值、時間與來源狀態碼後，再產生訓練標籤。路邊路段資料不作為路外停車場訓練資料。
