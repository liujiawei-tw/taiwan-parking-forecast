# 專案總覽

更新日期：2026-11-03。狀態：目前處於 Sprint 3 預測前置與訓練資料治理；新莊區是主系統現行試點，不代表已支援全臺或完整新莊。

## 產品目標

協助駕駛在前往目的地時，判斷附近路邊格位或路外停車場在抵達時仍有車位的可能性，並分開呈現官方觀測、資料時效、未知狀態與模型估計。產品提供停車決策參考，不預約或保留車位，也不保證抵達時一定有位。

長期方向是逐步建立全臺「有提供資料」停車場的查詢能力；各地資料覆蓋、更新品質與預測能力必須分別驗證，不能因為接入一種全臺資料來源就宣稱每個地區都可查詢或預測。

## 現行試點（已確認）

- **地理範圍**：目前主系統以新北市新莊區作為試點，服務範圍依程式設定的 MVP 矩形支援區判斷，不等於精確的新莊行政區邊界。現行附近查詢半徑為 500 公尺。
- **即時來源**：目前以新北市政府 Open Data 提供新莊試點的路邊與路外官方資料。TDX 尚未接入主系統，保留為全臺擴充與來源交叉驗證方向。
- **目錄範圍**：截至 2026-10-27，已同步的經審查目錄有 1,880 筆路邊格位、138 個路外場站；這是可用子集，並非新莊完整停車目錄。來源即時查詢候選與既有審查目錄仍有差異，覆蓋及汽車資格分類尚待治理。
- **預測範圍**：主系統目前只在符合輸入條件時顯示路外 30／60 分鐘實驗性估計；路邊預測仍為資料不足。任何預測都不能冒充官方即時空位。

## 使用者與價值

主要使用者是前往不熟悉目的地、需要比較周邊停車選項的汽車駕駛。產品目標是降低到場後才發現車位已滿的風險，同時讓使用者看見資料的來源與限制。

## 已同意的方向

- TDX 是逐步建立全臺資料能力的長期方向；開始介接時，須依官方文件確認端點、欄位、呼叫限制與實際費用，不把「可以存取」當成免費且無限制。
- 新莊試點先使用新北市政府 Open Data。各來源需經過欄位正規化、來源 ID 對應及品質檢查後，才可供主系統查詢。
- 官方目前觀測、模型估計和沒有資料要使用不同狀態表達。來源失敗或資料不完整時保留最後已發布完整快照，不以空值或舊值暗示「目前沒有車位」。
- `parking-data-collector` 是獨立的離線訓練資料收集器，不服務使用者、不提供主系統即時快照或 API，也不決定主系統刷新頻率。
- 主系統目前使用 Vue 3／Vite、Java／Spring Boot、MySQL、Redis 與 Docker Compose；產品需求、已決策事項和現況分別以 `docs/requirements.md`、`docs/decisions.md` 和 `docs/current-state.md` 為準。

## 第一版邊界

- 第一個主系統試點是新莊區的汽車停車資料，包含路邊格位與路外停車場；只呈現實際已收錄、已核對且符合查詢條件的項目。
- 目的地位於目前支援範圍外時，清楚提示尚未支援，不呼叫 Routes 或官方車位來源，也不以空清單表示附近沒有停車位。支援範圍內若資料覆蓋不完整，需標示缺口。
- 預計抵達時間只有在使用者設定起點且 Google Routes 可用時才計算；未設定起點時仍可查詢附近停車資料。
- Google Maps／Places 用於地圖與地點搜尋，Google Routes 用於路線 ETA；Google 地點資料不作為政府即時空位觀測。
- 車位預約、支付與內建導航不在第一版範圍。抵達時預測只有通過資料品質與回測門檻後才能宣稱為經驗證能力。

## 成功判斷

- 能量化不同資料來源在試點範圍的目錄覆蓋、汽車適用性與來源 ID mapping，並明確標示未知與缺口。
- 刷新有可追溯的請求、品質與耗時紀錄；只有完整來源遍歷可發布新快照，失敗時保留上一份完整快照。
- 各來源的呼叫頻率、額度和費用均有量測與上限；接入 TDX 前先確認帳戶實際額度及端點成本。
- 預測須以時間順序切分、可重現的標籤與回測證據評估，並檢查假陽性、校準、覆蓋率與拒絕率。未通過門檻時維持資料不足，不編造機率。
