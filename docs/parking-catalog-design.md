# 主系統停車位置目錄與汽車資格（Sprint 1 提案）

更新日期：2026-09-24。狀態：架構討論草案，尚未開始主系統 coding。此目錄由主系統獨立從官方資料建立；`parking-data-collector` 只收集離線 ML 訓練資料，不供使用者查詢。

## 目錄和動態觀測分開

目錄回答「位置在哪裡、是什麼類型、一般汽車能否使用」；動態快照回答「來源目前回報有沒有空位」。一個位置存在，不代表目前有位。目錄也不能因本次動態資料未出現一筆就立即刪除。

| 類型 | 目錄候選來源 | 動態來源 | 主要對接鍵 |
| --- | --- | --- | --- |
| 新北市路邊格位 | 新北市路邊停車空位資料中的 `cellid`、`name`、`day`、`hour`、`memo`、`latitude`、`longitude`、`areacode` 等欄位；須實測欄位值和穩定性 | 同資料集的 `cellstatus`、`parkingstatus` 等欄位 | 來源資料集 + `cellid`；若不唯一，須核對 `id` 與路段資訊 |
| 新北市路外場站 | 「新北市路外公共停車場資訊」中的 `ID`、`AREA`、`NAME`、`ADDRESS`、`TW97X`、`TW97Y`、`TOTALCAR` 等欄位 | 「新北市公有路外停車場即時賸餘車位數」中的 `ID` 與汽車剩餘位 | 來源資料集 + `ID`，先檢查靜態與動態是否一對一 |

上述是官方頁面列出的欄位，不等於每一筆實際值都可靠，也不代表路外目錄每個場站都有即時剩餘位。官方路外即時頁的說明寫 `AVAILABLE`，欄位清單寫 `AVAILABLECAR`，實作前須以實際 API 回應核對。官方資料集頁： [路邊停車空位](https://data.ntpc.gov.tw/datasets/54a507c4-c038-41b5-bf60-bbecb9d052c6)、[路外靜態資訊](https://data.ntpc.gov.tw/datasets/B1464EF0-9C7C-4A6F-ABF7-6BDF32847E68)、[路外即時剩餘位](https://data.ntpc.gov.tw/datasets/e09b35a5-a738-48cc-b0f5-570b67ad9c78)。

## 汽車格位資格與營運規則

- 原始 `name`／格種、`day`、`hour`、`memo` 等文字保留在來源欄位；未核對前不得由「有座標」或「回報空位」推斷一般汽車合法可停。
- 標準化資格先分 `confirmed_general_car`、`excluded`、`conditional`、`unknown`，並記錄判斷依據與規則版本。身障、裝卸、計程車、機車、特殊時段等限制不可直接算一般汽車位。
- `conditional` 只有在限制規則可可靠解析、且目標時點符合時，才可納入該時點的候選；第一版若無法可靠解析，當 `unknown` 處理。`isnowcash` 表示現在是否收費，不能單獨當作合法停車判斷。
- 目前空位推薦同時要求：一般汽車資格成立、現在可停、來源狀態為空位、座標可信、快照未過期。抵達時預測的格位集合應按 ETA 的資格判斷，不能直接沿用「現在可停」。
- 路外第一版使用官方 `TOTALCAR` 確認有汽車位，並核對是否有公眾可使用與營業時間限制；入口座標若未核實，不把場站中心冒稱入口。

## 更新與版本

1. 建立來源命名空間與穩定內部 ID；TDX 與新北市同名位置在 ID 對應驗證前不合併。儲存原始座標系、原值、標準化 WGS84 座標、位置核對狀態及來源最後見到時間。
2. 路外靜態目錄採較長、待量測的更新週期，與即時剩餘位擷取分開。路邊來源同時含相對靜態與動態欄位，可在成功取得**完整資料集**後比對目錄變動，但不因每筆使用者查詢而另抓目錄。
3. 對來源新增／修改／消失做差異紀錄。來源整輪失敗或分頁不完整時不改目錄；單次完整資料中的缺席也先標記待核對，不立即刪除或重用內部 ID。停用門檻依實際資料穩定性決定。
4. 在資料庫保留目錄版本、資格規則版本與已核對證據，讓 ML 樣本和線上 300 公尺查詢能說明當時用了哪些格位。細節和保留期限待資料量實測。

## 最小驗收案例

- 路外靜態 `ID` 有位置但動態 `ID` 無資料：顯示可信場站位置，車位數為未知，不是 0。
- 路邊來源回報空位但格種未知或僅限特定對象：不得列入一般汽車目前可停明細或「至少一格」預測標籤。
- 來源更新一輪失敗／少一頁／單筆暫時消失：保留最後完整目錄與快照的原時間，不把位置直接刪除，也不把過期空位當目前推薦。
- 來源新增格位或場站：只有座標、ID、車種／資格及來源關聯通過檢查，才可納入 300 公尺候選。

## 待查與面試證據

- 用實際新莊資料列出 `name`／格種、`day`、`hour`、`memo` 的不同值，與官方定義逐一對照；未知值比例、特殊格位比例是多少？
- 核對 `cellid` 是否唯一且穩定、靜態／動態路外 `ID` 對應率、TWD97 座標轉 WGS84 後的抽樣誤差，以及場站入口可取得率。
- 實測完整資料抓取大小、目錄變更率、更新耗時與 MySQL 附近查詢延遲，再定更新週期、索引和停用門檻。面試展示這些量測與降級案例，比只列框架名稱更能說明設計。
