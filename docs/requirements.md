# 需求與驗收條件

更新日期：2026-09-23。狀態：Sprint 0 草案，尚待 Sponsor 確認優先順序。

## 使用者需求

### R1 查詢目的地附近的停車選項

使用者輸入目的地與預計抵達時間後，能看到指定範圍內、TDX 或已核對的地方政府來源收錄的停車選項。每筆顯示名稱、類型、位置、來源及資料時間。若該地區沒有可用即時資料，明確顯示原因，而不是回傳空白或暗示都有車位。

### R2 區分觀測、估計與未知

有即時車位時顯示來源回報的剩餘數與更新時間。若資料缺值、過期或來源失敗，顯示不同狀態。模型補值只能標為「估計」，並顯示可信程度；不能顯示成官方即時數值。過期判斷門檻須依來源實測決定。

### R3 抵達時預測

第一版以新莊區作路邊與路外資料試點。路邊的產品問題是「抵達時，目的地附近範圍內是否至少有一個適用格位可停」；模型第一輪可先預測區域可用格數，並以有無至少一格作獨立驗收。路外先預測指定停車場抵達時剩餘的汽車位數，再評估有位風險。兩者共用時間與資料品質框架，但各自核對標籤與回測，不因輸出都是數量就視為同一模型。資料不足時顯示「無法可靠預測」。預測結果附模型版本與產生時間。區域半徑與預測時距仍待實測決定。

### R4 TDX 額度控制

一般使用者查詢不直接呼叫 TDX。排程擷取設有可設定的頻率、呼叫預算、失敗重試限制、資料過期規則和使用量監測。當額度接近上限時，服務降級仍可顯示最後可用資料及其時間。

### R5 多來源整合（第二期）

地方 API 的資料先轉成統一格式，保留來源及來源 ID；同一停車場不得重複顯示。欄位衝突時有可追溯的選用規則，不直接覆蓋原始觀測。

## 品質與驗證

- 保存資料來源、來源更新時間與系統取得時間；保留足夠歷史供回測。
- 以時間順序切分資料回測，避免使用預測當時尚不存在的資料。
- 監測「預測有位、實際無位」比例、資料過期率、縣市覆蓋率與每月 TDX 點數消耗。
- TDX 認證資訊不得提交至 Git；部署與本機設定方式需可重現。
