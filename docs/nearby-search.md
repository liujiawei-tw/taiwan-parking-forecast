# 目的地附近停車位置查詢（Sprint 1 設計提案）

> 狀態：核心查詢策略已決定，效能與索引仍待實測；尚未實作。`parking-data-collector` 僅供離線 ML 訓練，不參與此查詢或即時刷新。

## 已確認的產品語意

- 以使用者選定的目的地座標為圓心，查詢**直線距離 300 公尺內**的汽車路邊格位與路外停車場；圓周上的位置也算在內。
- 顯示附近實際有收錄的類型。停車位置目錄、目前官方車位觀測、抵達時模型預測是三種不同資料；找到一個位置不代表它目前有位。
- 路邊的主要預測結果是該圓內至少一個合格格位在抵達時可停的機率；路外則按停車場顯示抵達時有汽車位的機率。模型仍須驗證任意目的地圓形範圍是否適用。

## 候選查詢流程

1. Google 搜尋結果提供選定目的地的 WGS84 經緯度。若座標缺失或超出合理範圍，要求重新選定，不猜測位置。
2. 從 MySQL 的已核實停車位置目錄，用包住 300 公尺圓形的經緯度矩形先取候選，並先排除確認不適用一般汽車的位置。此步只是縮小資料量，矩形四角仍可能超過 300 公尺。
3. 在主系統對候選位置計算 WGS84 兩點間的球面直線距離，僅保留距離小於或等於 300 公尺者。接近邊界時注意浮點與座標精度；測試應涵蓋 299、300、301 公尺。
4. 固定路邊與路外各自目前啟用的完整快照版本，再把範圍內位置連到該版本的觀測；分別回傳來源取得時間、可用／0／未知／過期等狀態。來源缺觀測時仍可呈現可信的目錄位置，但不能標為目前有位。
5. 模型只使用符合其訓練與覆蓋條件的資料產生抵達時結果；預測值附目標時間、模型版本與可靠性狀態，不回寫官方觀測欄位。

矩形預篩加精確距離是第一版候選，實際 MySQL 查詢計畫、候選筆數與延遲尚需量測；若普通座標欄位的查詢不足，再評估固定 SRID 的空間欄位及索引。JPA 可用於目錄讀取，毋須為了附近查詢先更換 ORM。


## 第一版資料庫查詢策略（已決定）

第一版先採「MySQL 經緯度矩形預篩 + 後端精確距離計算」，不先把 MySQL spatial index 當必要條件。理由是新莊 MVP 的目錄規模可先量測，矩形預篩容易用 JPA／SQL 表達，且邏輯容易用測試案例驗證；若實測候選數或延遲過高，再升級為 `POINT` 欄位與 spatial index。

建議查詢邊界如下：

1. 後端收到目的地 WGS84 經緯度後，先計算 300 公尺外接矩形的緯度／經度上下限。
2. Repository 只負責依 `service_area`、`place_type`、`active_status`、汽車資格及經緯度上下限取候選位置；不要在 Repository 決定產品文案、資料新鮮度或模型狀態。
3. Application service 對候選位置計算精確直線距離，保留 `distanceMeters <= 300` 的位置，並把距離寫入 DTO。
4. Application service 取得路邊與路外各自 `source_state.active_snapshot_id`，再連到該已發布快照的觀測。沒有該快照觀測的位置可保留為位置已收錄但目前車位未知。
5. Response assembly 依 `area`、`roadside`、`offStreet`、`predictions` 的契約輸出；不得讓前端自行用座標和來源欄位判斷是否在範圍內。

Repository 層可有兩個主要讀取方向：一個查 `parking_place` 取得 300 公尺候選位置，一個依已發布快照與位置 ID 批次查 `availability_observation`。距離排序、數量限制及是否分頁仍待產品與效能實測；若第一版地圖只顯示 300 公尺內全部新莊候選，仍須避免一次回傳過多格位造成前端卡頓。
## 座標與邊界品質

- 內部目錄統一儲存 WGS84 經緯度及來源原始座標、座標系與核對狀態。來源若給 TWD97 等座標，於匯入時轉換並抽樣核對；不能把不同座標系直接比較。
- 無座標、超出臺灣合理範圍、座標順序顛倒或位置未核實的紀錄，不放入 300 公尺結果；保留資料品質原因供排查。
- 新莊只是試點資料覆蓋範圍，300 公尺圓可能跨到鄰區。若未收錄鄰區，結果需標示「收錄範圍可能不完整」，不可把沒收錄說成沒有車位。精確判斷跨界需要行政區邊界資料；尚未具備時，先揭露新莊試點的覆蓋限制。
- 路外場站資料座標不一定是車輛入口。對外導航位置須核實入口；路邊格位亦須檢查座標與實際可進入道路側，不能因落在 300 公尺內就保證導航可抵達。

## 與前端、刷新及 ML 的分工

- 地圖平移、縮放或展開詳情不自動更改本次目的地圓；使用者重新選定目的地才重算附近位置。按「更新車位」只更新官方觀測，不重新做 Google 搜尋與 ETA。
- 來源資料超過已選的 5 分鐘試驗門檻時，主系統先嘗試受控共用刷新；完整新快照未取得前，不把舊有位格位當目前推薦。
- 以固定路段或固定網格訓練出的機率，不能直接當作任意目的地的 300 公尺圓之機率；需確認訓練標籤、格位集合、觀測覆蓋率與線上查詢範圍一致。尚未驗證時顯示「預測資料不足」。

## 驗收與待決

- 用邊界內、邊界上、邊界外及矩形角落樣本驗證距離篩選；用只有路邊、只有路外、兩者都有、都無收錄的目的地驗證展示。
- 用跨新莊行政區界線、來源座標缺失與路外入口不同於場站中心的案例驗證警示與導航資格。
- 實測目錄規模、查詢延遲和索引效果後定資料庫實作；確認行政區邊界資料、汽車適用性判定及 ML 任意圓形範圍的最低覆蓋門檻。
