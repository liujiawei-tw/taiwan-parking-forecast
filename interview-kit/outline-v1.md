# 停車位抵達預測｜後端工程師面試簡報大綱

- 日期：2026-10-26
- 風格：`guizang-ppt-skill` 的橫向簡報節奏；色彩與無襯線字體沿用產品前端的暖米白、深綠與狀態色。
- 形式：單檔 HTML、程式碼繪製流程圖／UML；不使用生成圖片。觀眾頁只放結論、流程和必要術語；講者備忘承接說明。
- 對象：後端工程師面試官。頁面優先呈現 API 邊界、查詢協調、資料儲存、來源刷新和品質閘門。
- 時長：未指定，不預設每頁分鐘數。

| 頁面 ID | 觀眾看見 | 講者備忘目的 | 轉場 |
|---|---|---|---|
| `cover` | 專案目標、後端面試案例、新莊 MVP | 用一句話說明：可信的查詢來自明確的資料狀態與來源邊界。 | 先從一次查詢實際經過哪些責任開始。 |
| `query-flow` | 使用者查詢 → 目錄／快照 → ETA／觀測／估計 | 說明官方觀測、ETA 與模型估計分開；缺資料時保留原因。 | 將流程拆成後端元件。 |
| `backend-architecture` | Controller、Service、Adapter、MySQL、Redis、外部 API 與離線產物 UML | 點出 durable data 與短期 query state 的分工；離線 collector 不進入查詢路徑。 | 以單次 API 請求看清呼叫順序。 |
| `query-sequence` | API 時序圖與 `origin` 可選分支 | 沒有起點時不呼叫 Routes；查附近設施仍可完成。Redis 保存短期查詢狀態。 | 查詢讀既有快照；官方刷新是另一條流程。 |
| `source-refresh` | 官方來源分頁擷取、mapping／品質檢查、候選快照、發布流程 | 發布前驗證完整性；失敗不把不完整結果當最新資料。展示 2026-10-26 新莊來源盤點證據。 | 最後用工程取捨和技術棧收束。 |
| `backend-takeaways` | 三項後端取捨、技術棧、MVP 範圍 | 總結可追溯、可降級、可審查；預測仍標示實驗狀態，不擴大產品完成範圍。 | 留白收尾。 |

## 暫不放在觀眾頁

- 長篇 API JSON、錯誤碼清單、資料表欄位清單與技術詞典。
- Brier 分數、時間切分和模型實驗細節；這些容易把簡報帶離後端主題。
- 前端實作細節、AI 工具介紹及大量未完成項目清單。

以上細節由 repo 文件與講者備忘保留作為追問時的依據，不在主畫面逐條展示。簡報不保證面試官不追問，也不把實驗或局部 MVP 描述成全臺已完成。
