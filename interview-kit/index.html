先查得到附近設施，再判斷各資料區塊能不能回答

查詢、ETA、官方觀測與預測是不同結果區塊。某一項失敗或不足時，系統保留原因並降級，不以另一個區塊的值代替。

結果設計原則：觀測值、系統取得時間、ETA、預測機率和拒絕原因分欄呈現。顯示資料不足，是一種正確的產品回應，不是查詢失敗。
已實作查詢路徑可選／條件式外部呼叫明確保留的錯誤或資料不足

線上資料與主系統推論

  • 來源為新北市官方路邊／路外資料；目前以新莊 MVP 為範圍。TDX 全臺即時整合尚未完成。
  • 來源 mapping、品質／資格與完整性檢查後才發布快照；快照保留 source observed time 與 system fetched time。
  • 離線目前具備路外參數型實驗 artifact；API 可能在明確開啟實驗設定且所有護欄通過時回傳 EXPERIMENTAL。
  • 路邊預測仍是 INSUFFICIENT_DATA／null probability；S3-020 尚未完成准入。

訓練資料與實驗限制

  • 31 個私有 daily ZIP 中有路邊 2,522,054 列、路外 192,850 列；資料不提交 Git，也不包含在 API 回應。
  • 80/10/10 時間切分使用 25／3／3 個日期；test 僅三天，日期不是全新 holdout，泛化證據有限。
  • 路外 30／60 分鐘 calibrated persistence Brier 為 0.0115／0.0163；比較用固定 persistence 為 0.0130／0.0178。這是探索性回測，不等同正式模型准入。
  • 線上護欄：確認汽車資格、快照不超過 15 分鐘、狀態／剩餘位一致、ETA 已就緒，目標時距為 30／60 分鐘各 ±15 分鐘。

同一概念「資料收集」有不同用途：主系統官方來源刷新以產品查詢的 refresh API／來源 gate 控制；parking-data-collector 只提供離線歷史訓練素材。不得把 collector CSV、排程或時間戳稱為即時車位契約。

MySQL 保存可追溯來源資料

目錄、來源 mapping、ingestion run、availability snapshot、availability observation 與 source state 使用不同資料表。完整資料品質檢查後發布，避免部分下載變成最新快照。

Redis 保存短生命週期狀態

短期 queryId 與刷新鎖適合有 TTL 的狀態；Redis 過期不會讓 MySQL 中的來源觀測變新。Redis 失效時，查詢狀態可失效並提示重查。

外部 API 呼叫明確分支

Routes 只有在 origin 存在時才估 ETA；新建查詢不自動刷新政府來源。這讓上游用量、冷卻、失敗與使用者動作可區分。

模型產物受版本與資料護欄

小型參數 JSON 有 schema／feature／source 設定 hash，但仍標記 EXPERIMENT_ONLY。低樣本、過期資料、資格不確定、ETA 不足一律拒絕輸出機率。

API、錯誤狀態與分頁界限
  • 建立：POST /api/v1/parking-queries；requestToken 必填，destination 和 departure 必填，origin 可省略。
  • 查詢：GET /api/v1/parking-queries/{queryId}；map data 與 viewport 有各自端點。
  • Viewport：south/west/north/east 範圍、offset、limit；預設 300、最大 500。
  • 刷新：POST /api/v1/parking-queries/{queryId}/refresh；只接受 MANUAL_REFRESH 或 VISIBLE_AUTO_REFRESH。

技術名詞小字典
REST API（表現層狀態轉移介面）
以前端與後端可協作的 HTTP 資源和方法交換資料。
ETA（Estimated Time of Arrival，預計抵達時間）
由出發地、目的地及路線服務估算；未設定起點就不請求。
Snapshot（快照）
一次來源擷取經完整性與品質檢查後發布的資料版本。
Source mapping（來源對應）
把外部來源 ID 對到系統內停車位置，並保留來源與核對狀態。
Baseline（基準模型）
簡單且可解釋的比較方法，用於衡量較複雜模型是否有改善。
Brier score（布萊爾分數）
衡量機率預測與實際二元結果的平方誤差，越低通常越好；需搭配樣本與校準判讀。
Holdout（保留測試集）
未參與訓練或調參的資料；只有幾天的舊日期不能代表新的前瞻 holdout。
Graceful degradation（漸進降級）
某個上游或資料條件失效時，保留可用資訊並清楚標示缺口，而不是假裝成功。
